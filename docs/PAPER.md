# UROVIA PAPER — этап 1
Печать ранее созданных заданий без записи в БД. Кнопки в общем списке и в карточках предмета открывают отдельную страницу. Используется защищённый API test-preview.php, который возвращает вопросы без ключей ответов. Порядок соответствует существующему перемешанному предпросмотру; это не отдельный закреплённый вариант для автоматического оценивания.
- Печать A4 и сохранение PDF через диалог браузера, изображения, поля ФИО/класс/дата, баллы, задания с выбором, соответствием, порядком и письменным ответом.
- Нет назначения, изменения статуса или создания попыток. QR/OMR, персональные бланки, камера, журнал, тарифы ещё не реализованы.
- Следующий этап: отдельное бумажное назначение с неизменяемым снимком вопросов, вариантов и ключей; серверная проверка доступа к классу, школе и предмету; QR с непрозрачным идентификатором листа, уникальность результата, ручная проверка неоднозначных отметок. Интегрировать с attempts/answers и существующим оцениванием; явный источник paper и online, не допускать повторного начисления рейтинга и пересечения с активной онлайн-попыткой.
- Сейчас корневой .htaccess запрещает камеру. Для сканирования потребуется узкое разрешение на странице сканера, проверенное на iOS/Android, без ослабления остальных разделов.
- Ручные проверки: учитель и администратор открывают существующий тест с каждого списка, проверяют изображения и длинный текст в PDF, перемешанные задания на соответствие/порядок, отсутствие ключей, запрет доступа из чужой школы и ученика, пустое задание, отказ загрузки изображения. Проверить, что до и после печати нет новых attempts/answers/назначений, и обычный онлайн-режим не изменился.

## Этап 2 (черновой)
- Отдельный пункт учительского меню «Бумажные тесты», страница выбора задания, класса, ученика. Обычная печать по-прежнему доступна для всех типов.
- Персональный бланк с кодом, закреплённый сервером порядок вопросов/вариантов, отдельный лист А4 с маркерами; поддерживаются 1–36 вопросов выбора (2–4 варианта). Фото через файловый input, ручное указание четырёх углов, вычисление перспективы и локальное распознавание отметок; подтверждение всех ответов и последних восьми символов кода обязательно. QR и непрерывная камера пока не реализованы.
- Отдельная таблица paper_sheets создаётся только при обращении к бумажному API. Результаты записываются транзакционно в attempts/answers с termination_reason=paper, без вызовов онлайн start/submit/assign. Запись запрещена при существующей попытке или действующем онлайн-назначении ученику. Если задание изменилось после печати, автоматическая проверка блокируется. Повторная отправка возвращает сохранённый результат.
- Метки бумажного результата в журнале, разборе и оценках ученика. Шкала оценки берётся из существующей функции grade_from_percent_for_assignment. Фото не загружается на сервер. Существующие ограничения подписки сохраняются, специальные лимиты PAPER пока не введены.
- Ограничения этапа: автоматическая проверка только для тестовых вопросов, печать по одному ученику, без QR, без массовой печати, без тестов на реальном принтере/камере и без проверки PHP/MySQL интеграции. До слияния проверить создание таблицы, повторный запрос, смену школы, активную онлайн-попытку, ограничения роли, неверный код, изменение вопроса, нулевой результат, сброс результата и шкалу оценок. Проверить влияние существующих механизмов ремонта импортированных ключей на бумажные оценки.

### Дополнение: печать класса
Добавлена последовательная подготовка персональных комплектов для активных учеников класса (до 100 за операцию). Уже проверенные и онлайн-назначенные ученики, ошибки доступа или неподдерживаемые работы перечисляются как пропущенные. Комплект печатается одним диалогом; фактическая запись оценок по-прежнему только по одному ученику. Требуется браузерная проверка разрывов страниц.

## Этап 3: QR, камера, письменные вопросы
- Локальные QR-библиотеки (MIT qrcode-generator и Apache 2.0 jsQR, лицензии рядом с файлами), QR содержит только случайный идентификатор UP1. Автоматический поиск бланка ограничен школой, предметом, классом и правами преподавателя.
- Сканирование живого видео на отдельной странице, фиксация кадра при найденном QR и четырёх квадратных метках, ручное указание углов как запасной режим. Камера разрешена только на paper-workspace.html; поток останавливается при уходе со страницы. Фото и видео для QR и OMR остаются на устройстве.
- Персональные бланки: до 36 вопросов, до 6 вариантов; поддерживаются письменные, числовые, соответствия, последовательности. Учитель вводит транскрипцию, баллы по ключу или вручную. Развёрнутые ответы без ключа требуют явного выставления баллов. Проверка бланка обязательно подтверждается учителем. Старые процедуры пересчёта не изменяют бумажные баллы; итоговую оценку можно корректировать существующим инструментом журнала. Поответное редактирование бумажных результатов после сохранения отключено, чтобы сохранить снимок.
- OCR необязателен, выключен по умолчанию. После проверки правовых оснований и согласования школой администратор сервера может задать UROVIA_PAPER_OCR_ENABLED=1 и при необходимости UROVIA_PAPER_OCR_MODEL (по умолчанию qwen/qwen3.8-27b), используя уже настроенный Groq API. Перед каждой отправкой учитель должен подтвердить, что фрагмент обезличен и не содержит ФИО, QR или иных персональных данных. Распознавание возвращает черновик текста, не оценку. Фото не сохраняется сервером; фрагмент передаётся Groq только после включения и подтверждения. Без OCR сохраняется ручная проверка. Провайдер может быть недоступен; требуется отдельная проверка на реальном рукописном тексте.
- Автотесты paper-grading-smoke.php, paper-qr-smoke.cjs; GitHub Actions запускает проверки до FTP. Требуется проверка на реальных распечатках, iOS/Android и под учётной записью учителя. Ограничение: нельзя сохранить результат на ту же работу ученику с существующей попыткой/действующим онлайн-назначением. Для параллельного бумажного и онлайн-экзамена одному ученику используйте копию задания.

## Этап 4: отдельный кабинет
- Новые задания получают type=paper, собственный ID, вопросы, ключи и файлы. Копирование не переносит попытки, назначения или сроки. Оригинал не меняется. Тип paper исключён из онлайн-списка, онлайн-назначения и запуска ученика блокируются сервером; обычное тестирование остаётся прежним.
- Новый кабинет: справа навигация, карточки, поиск, отдельный конструктор всех девяти типов, добавление изображений, статусы проверки школы, печать и сканирование. На небольшом экране меню переносится наверх. При первом выпуске бланка статус paper_locked защищает содержание от редактирования; для изменений нужно сделать копию. Старые бланки онлайн-заданий не мигрируются, но доступны по QR при прежних проверках доступа. Новые персональные бланки создаются только для type=paper.
- Ограничения: до 36 вопросов / 6 вариантов для персонального бланка; импорт файлов через новый кабинет пока не добавлен, можно копировать уже импортированное онлайн-задание. Фактическая печать/камера и одновременное проведение в реальном классе требуют проверки на устройствах. Общий журнал и рейтинги используют отдельные ID работ и прежний признак termination_reason=paper.
